CodeQuest Bob · Problem
02 / 07
why this matters

New contributors do not need another code explainer.

They need a path from “I opened the repo” to “I can safely submit my first PR.”
  • Repository context is scattered across files, docs, scripts, and conventions.
  • Maintainers repeat setup, navigation, and first-task guidance.
  • Progress disappears after the session unless it becomes a visible record.

CodeQuest Bob · Product flow
03 / 07
demo path

The quest map is the product's center of gravity.

  • Repository intake creates the onboarding context.
  • Quest Map turns that context into Setup, Explore, Improve, and First PR.
  • Developer Passport records what the contributor learned and completed.

The demo path is simple: scan → quest → learn → package → record.

CodeQuest Bob · Architecture
05 / 07
system design

Architecture keeps IBM AI powerful, but credentials out of the browser.

Client product React screens show repository intake, quest map, Skill Boost Radar, First PR Package, and Passport.
Server-side proxy IBM keys stay server-side. The browser calls product APIs, not raw IBM credentials.
IBM services Granite, NLU, TTS, STT, Cloudant, and Bob session reports support the workflow.
Submission assets Generated artifacts and exported Bob sessions make the IBM Bob workflow reviewable.
